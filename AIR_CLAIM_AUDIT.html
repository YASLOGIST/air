AIR-01
No-go Credibility

The AWB validator rejects the site's own showcase waybill

lib/air-math.ts:64 · components/AwbModalAir.tsx:13–15, 82 · lib/i18n.tsx:270, 495 · components/FlightRadarHUD.tsx:256

The validator implements the IATA mod-7 check correctly. The showcase number does not satisfy it.

AWB 077-94821034 serial 9482103 9482103 mod 7 = 1 check digit printed = 4 → validateIataAwb() returns false

The modal hides this on open — useState(true) for both hasChecked and isValid paints "Valid IATA e-AWB Format (Mod-7 Verified)" before any check runs. Press Check on the untouched prefilled value and it flips to "Invalid Checksum (Mod-7 Failure)". The platform calls its own flagship consignment fake.

Remediation Change the literal to 077-94821031 in all five locations, and initialise hasChecked to false so the panel proves the result instead of asserting it.
AIR-02
No-go Legal · security

The security tab claims a Content Security Policy that does not exist

components/LegalModalAir.tsx:161

"Static asset delivery operates behind modern TLS encryption with strict Content Security Policies (CSP)." There is no CSP meta tag in index.html, no CSP in public/, and no header configuration anywhere in the repo. A false control assertion inside a document headed "Regulatory Compliance" is the worst place to carry one.

Remediation Ship the CSP (a <meta http-equiv="Content-Security-Policy"> permitting fonts.googleapis.com and fonts.gstatic.com covers this page's real needs), or delete the clause. Do not deploy with it unbacked.
AIR-03
No-go Cold chain

Sensor accuracy is stated two different ways for the same container

lib/i18n.tsx:273, 498 (±0.2°C) vs. :346, 391, 571, 616 (±0.5°C) · components/ULDSelector.tsx:67–68 (±0.5°C)

The radar caption advertises "RKN-Active-Envirotainer (±0.2°C Precision)" while the Stats benchmark, the Cargo Village step and the ULD spec sheet all say ±0.5°C — for the same RKN unit. A pharma client reads the tighter number as the SLA. Envirotainer's published RKN e1 tolerance is ±0.5°C.

Remediation Delete ±0.2°C from both language keys. One tolerance, sourced, everywhere.

AIR-04
Go ifData binding

"Target Window" renders values that are not times

components/CargoVillageFlow.tsx:189 · metadata at :28, 34, 44, 52

The detail panel binds activeContent.metric under the label "Target Window", but only step 1's metric is a duration. Steps 2–4 print "Continuous ±0.5°C Logging", "Instantaneous Digital Release" and "Immediate dispatch to highway" into a time field. The real times — T+15, T+40, PRE-TOUCHDOWN, < 180 MIN TOTAL — sit in FLOW_STEPS_META[].timeTarget and only appear in the small ribbon.

Remediation Bind currentMeta.timeTarget to "Target Window"; move the prose metric to its own labelled row.
AIR-05
Go ifCustoms · Nafeza

"Instantaneous Digital Release" misdescribes how ACID works

lib/i18n.tsx:352–353 (EN), 577–578 (AR)

Nafeza ACID is a pre-arrival regime: the ACID must be lodged and matched before the shipment sails or flies, and release still depends on inspection channel and duty settlement. "Instant cryptographic match" and "Instantaneous Digital Release" describe something Egyptian Customs does not offer — and the strength of the real mechanism is exactly that the work happens early, not that it happens instantly.

Remediation "Pre-arrival release — ACID lodged and matched before ETA, duty pre-settled, no document hold on landing."
AIR-06
Go ifIdentifier format

The ACID number is not shaped like an ACID number

lib/i18n.tsx:271, 496 · components/FlightRadarHUD.tsx:263 · components/AwbModalAir.tsx:118

2026-CAI-994108 is a plausible-looking invention. A real Egyptian ACID is a 19-digit numeric string with no separators and no IATA station code. Anyone who has filed one will spot it immediately — and the AWB beside it is presented as genuine, so the pairing reads as a claim, not a mock-up.

Remediation Use a correctly-shaped 19-digit synthetic value, and mark it a sample in the adjacent label.
AIR-07
Go ifModel integrity

Ocean transit is computed from the air great-circle distance

lib/air-math.ts:38 · surfaced at components/CargoSimAir.tsx:344

oceanTransitDays = distanceKm / 550 + 8 takes the flight distance and sails it. For the FRA ⇄ CAI preset that produces 13.3 days for a 2,910 km overland air path — and Frankfurt is not a seaport. The air-versus-sea card is the simulator's headline comparison, so this is the number most likely to be quoted back.

Remediation Add a seaDistanceKm and origin seaport per corridor (Hamburg/Rotterdam → Alexandria for the European lanes), or relabel the card as an indicative order-of-magnitude comparison.
AIR-08
Go ifModel integrity

"Air Transit Time (Doors)" is airport-to-airport block time

lib/air-math.ts:37 · label at lib/i18n.tsx:307, 532

distanceKm / 780 + 2.5 yields 6.2 hours for FRA ⇄ CAI and is labelled door-to-door. Door-to-door air freight runs in days. It also contradicts the hero directly above it, which sells the platform on resolving a 48-hour Cargo Village bottleneck (i18n.tsx:243) — a bottleneck this figure implies does not exist.

Remediation Rename to "Airport-to-Airport Block Time", or add pickup, export handling, ground dwell and delivery legs so the label is honest.

AIR-10
Go ifWCAG 2.1.1 A

The corridor and ULD selectors cannot be operated by keyboard

components/CorridorsAir.tsx:134–141 · components/ULDSelector.tsx:166–173

Both selection lists are <div onClick> — not focusable, no key handler, no role, no selected state exposed. A keyboard or screen-reader user cannot reach any corridor but FRA ⇄ CAI or any ULD but the RKN. AIR-11
AdvisoryAttribution

The CO₂ coefficient is cited to the wrong IATA document

lib/air-math.ts:3, 29 · components/LegalModalAir.tsx:133 · lib/i18n.tsx:302, 527

~502 g CO₂/tonne-km is a defensible long-haul freighter figure, but IATA RP 1678 is the passenger CO₂ methodology. Air-cargo emission factors belong to the GLEC Framework and EN 16258. The number is fine; the citation invites a correction from anyone who checks it.

Remediation Cite GLEC Framework v3 / EN 16258 and state the assumed load factor and aircraft class.

AIR-13
AdvisoryTelemetry realism

Mach is hardcoded against a jittering ground speed

components/FlightRadarHUD.tsx:213

MACH 0.81 (GS: {speed × 1.852} KM/H) prints a constant Mach while speed resamples every 2.5 s, and nests a ground-speed conversion inside a Mach parenthetical. The conversion itself is right — 485 kt → 898 km/h matches HeroAir.tsx:131–134 exactly. Only the Mach pairing is inert.

Remediation Derive Mach from speed and altitude, or drop it and show ground speed alone.
